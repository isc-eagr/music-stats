# Library graphs usability audit

Source review completed for the shared catalog Graphs layout, Playground navigation, chart rendering, category tables, filter handling, and the separate chart-ranking overview. The review did not start or restart the application. The manual checks below are intended for the existing local instance after the developer loads the updated build.

## Follow-up preferences

Male share is the highlighted percentage. Female-share sorting is removed. Chart ordering supports ascending and descending directions for total, male share, name, and year. One numbers table is always displayed. Its Total, Male, and Male % columns follow the selected measure; each remaining available measure has a single total column. The selected measure's total is not duplicated, and there are no repeated gender blocks or column toggles. Female and other/unknown values remain part of the totals and percentage denominators, but have no table columns. Every data column, including category name, sorts in both directions over all matching categories, independently of chart paging. Column headings expose the active direction and retain keyboard focus after sorting.

The filter catalog remains significant: Artists filters match artist metadata before expanding to associated songs; Albums filters match album metadata; Songs filters match effective song metadata and overrides. Keeping only Songs would change genre/language/gender override behavior, remove artist-only and album-only filters, and require a deliberate translation policy for existing links and saved filters. The three choices remain available.

## Implementation locations

- Navigation and API: `src/main/java/library/controller/PlaygroundController.java`, `src/main/java/library/util/GraphsNavigation.java`, `src/main/resources/templates/playground.html`, and the three catalog list templates.
- Explorer structure: `src/main/resources/templates/fragments/graphs-view.html`.
- Explorer state, presentation, and requests: `src/main/resources/static/js/playground-graphs.js` and `src/main/resources/static/css/playground-graphs.css`.
- Catalog filter editor: `src/main/resources/static/js/playground-graph-filters.js` and its stylesheet. Existing date controls use Flatpickr with `dd/MM/yyyy` display.
- Complete source-filter matching: `src/main/java/library/service/CatalogGraphFilterResolver.java`, `src/main/java/library/dto/ChartFilterDTO.java`, and the matched-scope branch in `src/main/java/library/repository/SongRepository.java`.
- Catalog table behavior remains in `src/main/resources/static/js/graphs.js`; its historical filename is retained to avoid unrelated asset churn. All existing hidden columns, extended statistics, gallery handling, sorting, and table pagination remain available. The old graph-only code and `graphs-view.css` are removed.

## Count semantics and remaining opportunities

1. **Song-based membership remains the baseline for filtered breakdowns.** The legacy category aggregation starts from Song. A filtered artist with no associated songs, or a filtered album with no songs, may be present in the catalog but absent from its graph counts. Unfiltered General retains the direct Artist/Album fast paths and includes those entities. Changing this would require a defined policy for source counts versus associated performers/albums and coordinated query changes, especially for group and featured scopes. The migration preserves the existing aggregation behavior.
2. **Listen-year item totals are not unique lifetime totals.** An artist, album, or song heard in more than one year contributes to each year. The explorer labels summary totals as totals across categories and explains the repetition. Plays and listening time sum across their actual play periods.
3. **Complete matching has a backend cost.** Unfiltered exploration skips the catalog matching query. A filtered scope obtains all matching source IDs, with no catalog-page limit and no requested extended display statistics. Each uncached breakdown still repeats that matching query and performs its existing aggregate queries. If measured latency warrants it, extract a shared IDs-only query projection or cache matching sets by canonical filters, source, and catalog revision. Keep account, date, scope, metadata, and import changes in any invalidation policy.
4. **Comparisons preserve units.** Comparing artists, albums, songs, plays, and time as raw totals is intentional; they should not share an unlabeled numeric axis. The single table preserves each measure's units and sorts raw numeric values, including seconds for listening time. A future explicit two-measure comparison could add aligned small multiples if there is a concrete use case.
5. **Catalog mode defaults remain compatible.** Existing catalog APIs generally make filter modes optional, and their repository helpers ignore absent modes. The resolver follows those same rules rather than inventing defaults for bookmarked URLs. The filter editor sends the selected includes/excludes/null/date/chart modes explicitly. A separate normalization change should update both catalog and graph entry points together.
6. **Exports and drill-down are possible follow-ups.** Exporting the selected breakdown or opening a category as a filtered catalog could improve investigation, but the target source and override semantics should be explicit. Neither is required to navigate the migrated explorer.
7. **Large numbers and long names need runtime visual checks.** The new layout wraps names and reduces mobile columns, but real library data at browser zoom and narrow widths should be checked with the manual cases below. Native details/table behavior and tab focus should also be exercised with a screen reader.

The separate `templates/charts/overview.html` page describes weekly/seasonal/yearly ranking performance, rather than library composition. It is not part of the Graphs-layout migration. Its existing sticky table header and more readable spacing were useful reference patterns. A later, separately scoped review could address its wide table, Shift-click-only multi-sort discovery, image-click keyboard access, expansion-button names/state, and the infinite-scroll failure path that currently logs an error without an inline Retry control.

## Focused verification

Automated coverage accompanies navigation and template changes, explorer normalization/state/request handling, filter editing, and the resolver. Resolver tests exercise real SQLite catalog queries for all three sources, metadata overrides, tag/image/date/chart predicates, account/date play windows, mode-only null filters, empty matches, artist group/featured scopes, iTunes/full-listen field forwarding, large JSON ID sets, and invalid typed inputs. The final implementation check is the repository-required Maven package build; its result is reported with the completed task.

Manual checks for the developer's existing local instance:

1. Open Playground and switch among Year activity, Flashback, and Library graphs. Verify that only Cards and Table remain in each catalog and that an old filtered `?view=graphs&tab=...` link opens the matching Playground scope.
2. Compare one filtered artist, album, and song selection against its catalog. Include an artist/album whose songs override genre, language, or gender; a tag filter; an image-theme filter; a chart date/mode filter; and an album full-listen condition.
3. Apply a Last.fm account and a `dd/MM/yyyy` played-date range. Check that Plays and listening time use the selected account/window and that clearing filters restores the full-library view.
4. Change every measure and scale, inspect all breakdowns, then search for a category and page through it. Confirm that paging/search do not alter summary totals and that Release year makes Artists unavailable without trapping navigation.
5. Change the selected measure and check that Total, Male, and Male % follow it, with one total column for every remaining measure and no duplicate total. Check every column's ascending/descending sorting and the sticky category column when scrolling. Confirm male/blue values against bar descriptions, including all-zero rows and very small shares. Female and other/unknown values remain in bar segments and total/share denominators, but not as table columns.
6. Test no matches, a category search with no results, and a failed chart request followed by Retry. Change breakdowns or filters quickly while the network is slow; the last selection should win.
7. Reload a customized URL, then use Back and Forward. Check source, filters, breakdown, measure, chart order/direction, scale, category search/page size, and independent table column/direction.
8. At a narrow mobile width and at 200% zoom, navigate using only the keyboard. Check focus visibility, meaningful labels, wrapping names, table scrolling, details controls, and pagination boundaries. No graph task requires starting or restarting the application from an agent.
